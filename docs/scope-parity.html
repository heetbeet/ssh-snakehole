ssh-snakehole specification / 1. Scope and parity

What the package must do

The agreed Python boundary

The user's clarification permits standard Python libraries that are integral to ordinary Python installations. This design therefore permits ssl, hashlib, hmac, secrets, socket, asyncio, subprocess, filesystem APIs and their interpreter/OS implementation. OpenSSL behind ssl is allowed. The package need not implement TLS or SHA in Python.

Additional runtime dependencies MUST contain Python source and data only. The package MUST NOT import cryptography, PyNaCl, bcrypt, PyCryptodome, libssh/ssh2 bindings, QUIC bindings or compiled accelerators. It MUST NOT launch Iroh, an installed SSH daemon, a wormhole executable, OpenSSL's CLI or another networking helper to implement its protocol. It MUST NOT use ctypes, cffi or an undocumented standard-library escape hatch to load those libraries. Being reachable through a standard module does not turn a third-party crypto library into standard Python.

Conditionally available OS modules may be used by the relevant adapter, such as winreg and msvcrt on Windows, or fcntl and os.geteuid on Unix. They MUST NOT be imported unconditionally. The public library must import on every supported system. Standard-library ctypes is allowed for narrowly scoped calls to the operating system's own process/security APIs. The wrappers are Python code; the OS is an explicit platform boundary, just as it is for sockets/subprocess. This permission does not allow loading native application, transport or crypto libraries.

Executing a requested program is the payload of remote access, not an implementation helper. The default executor may start the OS's shell through subprocess. A library caller can instead supply an executor. The Python package cannot port every program an agent might ask the target to run.

Audited baseline

The source baseline is SSH Magic v0.1.6, commit 6c8e1517a236296103f22c9c11fd6f0e3c2db0ac. The Go CLI, runtime, Windows/Linux platform adapters, installers, bootstrappers, dependency manifest and Iroh source manifest were inspected. The current released platform set is Windows/Linux x64; macOS was requested but is not an implemented baseline feature.

R13Secrets do not enter ordinary logs, subprocess arguments, unencrypted credential stores or shared temporary files.
R14Malformed or hostile protocol input has resource bounds and cannot downgrade security.
R15Release requires crypto review, conformance vectors, independent interoperability and measured performance.

Explicit exclusions

No compatibility layer for SSH Magic tickets, no full Magic Wormhole file-transfer tool, no Iroh wire compatibility, no GUI desktop control, no persistent remote service, no automatic account creation, no silent privilege escalation, no port/agent/X11 forwarding and no general SSH algorithm catalogue. Interactive PTY support is excluded from v1 because a portable Windows terminal requires additional OS integration. Piped shell/exec sessions remain required.

The package supplies powerful account-level remote execution. It is not a sandbox for an untrusted operator. Applications needing narrowly scoped actions should embed the executor and file policy described in the API chapter.
