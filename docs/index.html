ssh-snakehole / specification v0.1 / 7 October 2026

Temporary SSH, as a Python library

One person opens access and reads out a short code. Another person or an agent redeems it, runs commands and transfers files through genuine SSH, then closes access. Both computers make outbound connections, so the normal internet workflow needs no router configuration. The host runs in the foreground under the person who opened it.

This repository specifies a new product. It does not contain an implemented or security-reviewed SSH stack. The design allows Python's standard library, including its native internals. It excludes additional native extensions, manually loaded crypto DLLs and networking helper executables.

The chosen structure

The core is an asyncio library named ssh_snakehole. Python's ssl handles TLS and certificate validation. A small, source-audited pure Python WebSocket dependency carries Magic Wormhole pairing. The used SPAKE2 and SecretBox operations are ported to Python. Magic Wormhole Transit replaces Iroh and carries an SSH byte stream. A focused Python SSH client/server and SFTP v3 implementation provide the actual remote access.

The simplest default uses a relay for bulk traffic. Direct TCP is an explicit deployment option. QUIC, automatic UDP hole punching, network migration and Iroh endpoint compatibility are excluded from the first product. That is a deliberate transport replacement, with different availability characteristics. Reimplementing Iroh would be a much larger project.

Standard Python does not expose the raw X25519, Ed25519, XSalsa20 or SSH ChaCha20 operations this needs. Those are the remaining difficult ports. Their correctness, performance and timing behavior must pass release gates before this becomes a tool people rely on.

How to use this document

MUST and MUST NOT are product requirements. SHOULD identifies a default that needs a documented reason to change. Existing behavior is evidence from SSH Magic, not a promise that a Python replacement already delivers it. Proposed signatures and commands describe the target API. Source references distinguish upstream facts from our design choices.

The dependency ledger accounts for the current product's direct and indirect Go dependencies, its Iroh transport and the proposed Python replacements. Source pins make the research reproducible. No code from a candidate is approved merely because it appears in the ledger.

Four decisions that shape the work

  1. The revised definition of pure Python includes ordinary standard-library imports. Porting TLS, SHA or operating-system socket code would add work without serving that requirement.
  2. Keep real SSH interoperability. A custom command protocol over TLS would be easier but would not satisfy SSH clients and agents.
  3. Use Transit rather than porting Rust's QUIC ecosystem. Reconnect uses a live host and a session ticket; commands are never replayed automatically.
  4. Keep credentials in memory in the library. An optional encrypted CLI vault supports separate command invocations without claiming Windows chmod enforces Unix permissions.

Platform adapters may use standard-library ctypes for built-in OS security/process APIs. They must not load native crypto or transport code. The platform chapter specifies Windows Job Object ownership, Linux parent-death handling and the remaining cleanup/elevation limits. The project must not claim stronger guarantees than it demonstrates.
