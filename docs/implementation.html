ssh-snakehole / 0.5.2 / 9 October 2026

Test evidence and boundaries

AsyncSSH owns SSH and SFTP. aiortc and aioice own ICE/STUN, DTLS and reliable ordered SCTP data channels. cryptography supplies key and HKDF operations, PyNaCl supplies authenticated encryption, spake2 supplies the PAKE used by Magic Wormhole, and bcrypt protects exported OpenSSH keys. wsproto and h11 handle WebSocket framing. The package owns pairing transcripts, relay rendezvous, temporary process lifetime, inactivity and transfer publication policy.

There is no custom cipher, curve or SSH packet engine, bootstrap script, PATH editing or installer service. Process specifications and audit logs remain locally in ignored docs/temp.

ICE transport and recovery

Fresh SDP offers and answers travel encrypted over the authenticated Transit rendezvous. Their key is derived with a separate HKDF domain. A sender-led selection exchange chooses direct UDP or relay before SSH starts. ICE credentials and certificate fingerprints are fresh for every connection and are never saved to tickets. Both routes still require pinned Ed25519 SSH identities. The original relay socket stays open until a direct session closes, avoiding a teardown race during selection; it carries no SSH data on that route.

The data channel is reliable and ordered, with no partial-reliability limits. Application consumption credit bounds queued payload to 256 KiB; frames carry at most 1 KiB. SDP and encrypted signalling are capped. aiortc handles retransmission, congestion control, DTLS authentication and ICE consent checks. Application code does not implement a custom reliable UDP protocol.

Failed selection cannot hand off an uncommitted stream. Queued UDP shutdown also exposed CPython #156920 on Windows: after a bounded graceful-close wait, owned datagram sockets are aborted and aiortc teardown finishes. The required socket access is confined to pinned aioice internals during teardown. Tests corrupt authenticated signalling, exceed receive credit, cancel binding and close blocked writers.
Recovery and interfaceSave the encrypted ticket and print the new token before initial SSH setup. Failed setup remains resumable. Fresh connections retry ICE and select relay when needed; interrupted commands are never replayed. Explicit operator STUN configuration is honored. Cross-platform transfers exposed a 1280-byte VPN path where larger SCTP datagrams stalled. Stream frames are now 1 KiB, verified with a small-MTU packet filter and real Windows/WSL transfers in both directions. Version 0.4.0 starts a new protocol; earlier tickets are not converted.

SSH terminals

AsyncSSH accepts native shell, PTY, window-change and signal requests. Unix uses ptyprocess; Windows uses pywinpty ConPTY on Windows 10 1809 or later. PTY workers start containment before remote payloads. The client forwards raw input and restores local terminal modes after normal exit, cancellation and failures. Open shells count as active work until their channel ends.

Windows remote terminals begin on a fresh viewport, matching ConPTY's initial cursor origin. Existing local content and the reconnection token move into scrollback. The host answers ConPTY's initial capability query to avoid its three-second wait when a nested local console consumes replies. Later application queries still reach the client. PTY output drains without a sleep after successful reads, and the Windows local SSH bridge disables TCP Nagle on both sockets.

Both ICE peers gather candidates concurrently while Transit connects and authenticates. A regression STUN server withholds replies until both peers query it. Another test streams 128 KiB over a simulated 160 ms round trip, checking that output is pipelined rather than acknowledged one message at a time. Existing tests cover loss, reordering, low MTU, bounded buffering and relay recovery.

The first terminal audit fixed Ctrl+C killing the Unix lifetime watcher and improved output draining, signal status and worker task error handling. The second fixed asyncio closing the client's original stdin, checked actual terminal restoration, removed custom prompt commands and added binary CLI stdin. Final cancellation checks also found repeated close events interrupting subprocess pipe cleanup; cleanup is now shielded and early-timeout tests check for leaked transports. Pipeline tests exercise interactive Python, persistent state, colors, Unicode, resizing, Ctrl+C, reconnection and disconnect cleanup. Independent OpenSSH also opens a PTY and runs Python interactively.

The Windows client uses ReadConsoleW with VT input, an owned cancellable reader and incremental UTF-16/UTF-8 conversion. It suppresses ConPTY's private Win32 key-mode requests so input also works with Unix peers. Terminal tests use the xterm parser for actual cursor-position replies. A Textual editor exercises alternate-screen entry and exit, cursor editing, multiline paste, combining characters, CJK, emoji and resize through the installed CLI.

SSH does not negotiate encoding. Unix PTYs and all exec streams preserve bytes. Windows ConPTY requires UTF-8 terminal input and rejects invalid or incomplete input instead of replacing it. Tests split multibyte input across SSH writes and round-trip Latin-1 and binary exec data. These checks do not guarantee every application's terminal compatibility; application-specific console APIs and terminal emulators can differ.

A same-computer comparison with native OpenSSH and Codex 0.156.1 found dropped emoji in Snakehole. ConPTY generated interleaved surrogate key-down/key-up events that raw-key applications mishandled. Windows terminal input now submits supplementary Unicode as paired key-down events using Microsoft's Win32 input protocol. The PTY backend, Ctrl+C behavior and exit-status handling are retained. A raw-key reader and the Textual editor cover both Windows input APIs.

Relay TLS

A remote Windows test reproduced certificate expiry with Python's imported Windows trust store while the same relay certificate verified with certifi. Secure WebSocket relays now use certifi's Mozilla roots. SSL_CERT_FILE and SSL_CERT_DIR support an explicitly configured private trust store. Local TLS tests reject untrusted, expired and wrong-host certificates; none of these errors trigger an insecure retry.

Command startup

Fresh command workers load only containment and framing modules, without importing SSH, crypto or pairing dependencies. In local Windows measurements this reduced echo hello from 0.42 to 0.45 seconds to 0.22 to 0.23 seconds. On the reported public-relay session, transport round trips took 1.10 to 1.14 seconds and echo hello took 2.83 to 2.88 seconds before the host update. The import change does not remove relay latency. The source, installed wheel, public API exports and worker import boundary are checked.

Boundaries

This remains a work in progress without an independent security audit or public PyPI release. Protected admin mode, real independent ISP/router combinations and sustained multi-gigabyte workloads need further validation. Upstream spake2 uses Python point arithmetic; importing established packages does not provide a blanket constant-time guarantee.

Encrypted tickets protect against copying files. Malware controlling your account or reading permitted process memory can capture live credentials. The token must stay private; another computer also needs the encrypted ticket. Saved status describes the invitation, not current online availability. Each host session shares one inactivity clock and authorization. Closing it revokes every controller using that session.

Public relays must be reachable. Direct routing uses temporary UDP sockets. There is no public TCP listener, HTTP proxy or automatic 443 fallback. Commands and SFTP have the host account's rights. Interactive connections provide native shells and PTYs. Separate exec calls start independent commands. Port forwarding, agent forwarding and legacy SCP are not provided. Host connections are capped at eight, active sessions at sixteen per connection and sixty-four per process. Stream windows are 256 KiB; transfer chunks are 32 KiB and native SFTP reads are capped at 4 MiB.

Windows Job Objects and Unix process groups with a temporary pipe watcher stop ordinary owned descendants. They do not sandbox a hostile operator. Filesystem work finishes before its descriptor closes on cancellation. Blocking network filesystem calls cannot be forcibly interrupted; local filesystems are the supported boundary.

Transfers publish sibling temporary files with no-overwrite linking or atomic replacement. A lost publication reply leaves commit state unknown. Confirmed linking followed by failed temporary removal reports committed=True. Fsync does not promise directory persistence through power failure.

Native OpenSSH export creates a new private directory containing an encrypted key, pinned host file, config and route metadata. It refuses existing directories and unsafe config paths, cleans partial failures and modifies no global SSH settings. The package creates no service, scheduler entry, PATH edit or SSH daemon. Software and file changes made by the operator remain after close.
