ssh-snakehole / 0.3.0 / 8 October 2026

Test evidence and boundaries

AsyncSSH owns SSH and SFTP. cryptography supplies key and HKDF operations, PyNaCl supplies authenticated encryption, spake2 supplies the PAKE used by Magic Wormhole, and bcrypt protects exported OpenSSH keys. wsproto and h11 handle WebSocket framing. The package owns pairing transcripts, relay rendezvous, temporary process lifetime, inactivity and transfer publication policy.

There is no custom cipher, curve or SSH packet engine, bootstrap script, PATH editing or installer service. Process specifications and audit logs remain locally in ignored docs/temp.

Verified evidence

The 52-test suite runs in CI on CPython 3.11, 3.12, 3.13 and 3.14 on Windows, Linux and macOS. All twelve combinations pass. Local Windows x64 and Ubuntu 24.04 WSL tests also run as non-admin users on CPython 3.12.14. Windows skips three POSIX-specific tests; Unix skips the Windows Job Object test.

Tests cover host pinning, public-key authentication, fragmented relay workflows, command streams and exit status, output limits, explicit timeouts, descendant cleanup, binary files, transfer collisions, cancellation, ticket tampering, shared-session revocation and independent sessions. Short test inactivity intervals exercise silent commands longer than the interval, overlapping work, transfer handle cleanup, keepalive renewal and explicit hard lifetime expiry.

POSIX pseudo-terminal tests exercise hidden CODE entry, commands, exit, hidden token entry and close. A local Windows console test also exercises hidden CODE entry, a streamed PowerShell command and confirmed close. Installed CLI tests cover connect, exec, put, get, periodic keepalive and close. Native SSH/SFTP tests exercise rekeying; they verify encrypted exported keys, then decrypt only the test fixture for unattended OpenSSH invocation.

An independent upstream Magic Wormhole peer verifies SPAKE2, version negotiation and encrypted phases. Installed packages pass both roles across Windows and Linux through the public mailbox and Transit relays, including binary stdin/stdout, exit status 7, a 51,200-byte transfer, reconnection and host closure. Both peers share a physical network; separate-NAT validation remains pending.

Build checks compare every runtime module in the wheel with its source bytes. CI installs dependencies from binary wheels and tests the installed package with isolated Python. Offline wheelhouse installation was exercised on Windows in the previous sprint. pip-audit checked all ten pinned runtime dependency distributions on 8 October 2026 and reported no known vulnerabilities.

Boundaries

This remains a work in progress without an independent security audit or public PyPI release. Protected admin mode, separate-NAT operation and sustained multi-gigabyte workloads need further validation. Upstream spake2 uses Python point arithmetic; importing established packages does not provide a blanket constant-time guarantee.

Encrypted tickets protect against copying files. Malware controlling your account or reading permitted process memory can capture live credentials. The token must stay private; another computer also needs the encrypted ticket. Saved status describes the invitation, not current online availability. Each host session shares one inactivity clock and authorization. Closing it revokes every controller using that session.

Public relays must be reachable. There is no direct listener, HTTP proxy or automatic 443 fallback. Commands and SFTP have the host account's rights. The foreground command prompt runs independent commands; it does not provide a PTY, persistent shell, forwarding or agent forwarding. Host connections are capped at eight, active sessions at sixteen per connection and sixty-four per process. Stream windows are 256 KiB; transfer chunks are 32 KiB and native SFTP reads are capped at 4 MiB.

Windows Job Objects and Unix process groups with a temporary pipe watcher stop ordinary owned descendants. They do not sandbox a hostile operator. Filesystem work finishes before its descriptor closes on cancellation. Blocking network filesystem calls cannot be forcibly interrupted; local filesystems are the supported boundary.

Transfers publish sibling temporary files with no-overwrite linking or atomic replacement. A lost publication reply leaves commit state unknown. Confirmed linking followed by failed temporary removal reports committed=True. Fsync does not promise directory persistence through power failure.

Native OpenSSH export creates a new private directory containing an encrypted key, pinned host file, config and route metadata. It refuses existing directories and unsafe config paths, cleans partial failures and modifies no global SSH settings. The package creates no service, scheduler entry, PATH edit or SSH daemon. Software and file changes made by the operator remain after close.
