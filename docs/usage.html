In the foreground prompt, remote commands run independently through PowerShell or /bin/sh, with no persistent shell environment or PTY. close revokes the whole host session; exit, EOF and operator Ctrl+C disconnect only this client. Host Ctrl+C revokes immediately. Multiple controllers may share accepted credentials; closing that session ends all of them. Separate open invocations are independent.

Connection setup tries ICE with local and STUN-discovered addresses. When UDP punching succeeds, SSH runs over a reliable, ordered WebRTC data channel. Otherwise it uses the existing relay. The prompt shows direct-udp or relay. Some routers change ports between destinations and some networks block UDP; direct routing is not guaranteed. Setup may take several seconds. Keep the same Python Session for repeated work.

A reachable Transit relay is still needed for encrypted connection negotiation. Default STUN is stun.l.google.com:19302. Before the subcommand, --stun stun:HOST:PORT selects another server; --stun none gathers local addresses only. No router settings or global firewall rules are changed.

Recovery

The encrypted ticket is saved and its token printed before initial SSH setup. If that setup fails, use resume with the token. With connect --detach, retain the stdout token even on unsuccessful exit. For the API, ConnectTimeout and RelayUnavailable carry the accepted ticket in error.ticket.

If an established connection breaks, reconnect using the token or session.ticket. Each new connection tries ICE again and may fall back to relay. There is no transport switch or command replay within an established SSH connection. OutcomeUnknown means an interrupted command has no confirmed result: inspect its effects before retrying. File publication and remote close can also remain unconfirmed after a lost reply. Both peers need 0.4.0; create a fresh invitation after upgrading. Earlier tickets are not converted.

Inactivity and long work

Access expires after 30 minutes of inactivity. Commands and open regular-file transfers pause the host timer. The full interval starts after the last active operation finishes, including nonzero command exits. Long silent commands have no implicit timeout. --timeout on exec is optional. An optional host --lifetime SECONDS is a hard limit that overrides active work; no hard lifetime is imposed by default.

Authenticated keepalive renews inactivity; so does a normal completed command such as echo keepalive. Idle transports, cached SFTP channels without open files and automatic SSH keepalives do not. A controller must stop its foreground keepalive process when finished. No service or detached process is installed.

Agent input and API

Prefer the importable connect(code) context and retain its Session for repeated run/run_argv/exec/put/get calls. API credentials remain in memory unless explicitly saved. session.exec exposes byte streams; read(32768) reads a chunk and read() waits for EOF. session.keepalive renews access without a remote shell command. Captured run output defaults to 8 MiB. Lost commands are never replayed.

For separate processes, launch connect --code-stdin --detach with CODE supplied through a trusted stdin pipe. It returns only the token on stdout. Follow-up commands use --token-stdin. The token selects the session directly; no extra ID is needed. Do not place secret literals in shell commands, tools, environment assignments or temporary files. The trusted runner must not record input or token output. Default hidden prompts refuse echoing fallbacks. Optional positional CODE is for trusted command lines only; disabling history does not hide process arguments. CODE and --code-stdin cannot be combined.

The reconnection token has 256 random bits, independent of CODE. Local credentials are authenticated encrypted and owner-protected; neither secret is saved. Another computer needs both token and encrypted ticket. Do not place tokens on the clipboard. File-copying alone cannot unlock them; malware controlling your account can still capture input or permitted process memory.

Native SSH

export-ssh NEW-DIRECTORY prompts for the token and exports an encrypted OpenSSH private key, pinned known-hosts file, config and route metadata. It refuses existing directories and unsafe config paths. Run the printed ssh command; OpenSSH asks for the same token as its private-key passphrase. Route metadata contains no operator private key. The Python API is simpler for agents. No global SSH settings are changed. PTYs, shell requests, forwarding and legacy SCP remain rejected.

Offline installation

Prepare on matching OS, CPU and Python:

python -m pip install build
python -m build --wheel
python -m pip download --only-binary=:all: --dest wheelhouse dist/ssh_snakehole-0.4.0-py3-none-any.whl

Copy wheelhouse to the offline computer:

python -m pip install --no-index --find-links wheelhouse ssh-snakehole==0.4.0

Installation is offline; pairing and SSH still require a reachable relay.

Admin and cleanup

Default mode refuses elevation. Admin mode requires an already elevated terminal, isolated Python and a protected installation including all dependencies: python -I -m ssh_snakehole open --admin. There is no automatic elevation or custom installer. Protected admin lifecycle validation remains pending.

Close stops ordinary owned commands, but intentional file/software changes remain. Deliberately detached processes and newly installed services are outside cleanup. Encrypted tickets can remain after remote inactivity expiry; forget removes them. Invitations expire after ten minutes and first SSH authentication must follow pairing within two minutes.

Default pairing uses outbound TLS WebSockets and Transit uses outbound TCP 4001. ICE opens temporary UDP sockets, performs authenticated connectivity checks and uses STUN for address discovery. Those sockets close with their SSH session. An explicit binary WebSocket relay can be supplied where that port is blocked. Both sides establish SSH using the pinned identities obtained through SPAKE2.
