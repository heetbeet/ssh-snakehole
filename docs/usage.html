ssh-snakehole / working commands / 0.1.0

Open access, share a code, finish, close

Download the local dist/ssh-snakehole.pyz, or extract the offline ZIP. Existing CPython 3.12.14 or newer, through 3.14, is required. These commands run from PowerShell, cmd, Bash or Zsh. Use python3 on Unix if that is your interpreter's command.

The GitHub download bootstrap URLs are prepared but have not been published. The commands below work with the built local artifact. This experimental Python SSH implementation has not had an independent security audit.

In cmd use double quotes around a command. In PowerShell/Bash single quotes preserve command text. On the Windows host command text runs through PowerShell; on Unix it runs through /bin/sh. The Python run_argv() API bypasses shell parsing.

Agent use

The simplest agent path is the importable API. Give the agent the one-use code, ask it to connect, make the requested changes and call close_host(). Keep a ticket in memory to reconnect for additional operations during the same host lifetime.

import asyncio
from ssh_snakehole import connect

async def assist(code):
    async with connect(code) as session:
        result = await session.run("COMMAND")
        result.check_returncode()
        print(result.stdout.decode(errors="replace"))
        await session.close_host()

asyncio.run(assist(code))

For repeated CLI invocations, supply the vault passphrase through the agent's secret environment, SSH_SNAKEHOLE_PASSPHRASE. Use the ticket ID after pairing; the original code is consumed. A failed SSH attempt leaves the accepted ticket available. An interrupted command has an unknown outcome and is never automatically replayed.

export-ssh ID DIRECTORY writes a dedicated native SSH config, pinned known_hosts and an unencrypted private key to a private directory. It prints the native SSH command. This is an explicit export, so delete that directory when finished. It does not change the global SSH configuration. Modern SCP can use this SFTP endpoint; legacy SCP and PTYs are unsupported.

Permanent and offline installation

Extract ssh-snakehole-0.1.0-offline.zip and run python offline-install.py. It needs no network access, pip or compiler. The archive bundles this package, wsproto, h11, word lists and license notices. Python itself is supplied by the computer.

Windows places versioned archives and a .cmd launcher under %LOCALAPPDATA%\Programs\ssh-snakehole and updates only that entry in HKCU PATH. New terminals receive it. Linux/macOS place archives under ~/.local/share/ssh-snakehole and the command under ~/.local/bin. If needed, installation adds one marked PATH line to .profile or .zprofile. Unusual shells may need a manual PATH setting. Updates keep recent archive paths available for running sessions.

Admin and user access

Default mode uses the account that opens access and refuses an elevated interpreter. Administrator access requires a protected installation, an already elevated terminal and isolated Python: python -I C:\Program Files\...\ssh-snakehole.pyz open --admin, with the path quoted. On Unix the Python installation and archive must be root-owned without group/public write permission. On Windows the checked installation must be under Program Files or Windows and owned/writable only by trusted administrators/system identities. The convenience user installer does not perform elevation or create a protected admin installation.

Closing access stops the host and its owned commands; it does not undo intentional software installation or file changes. No background service or network rule persists. The default lifetime is two hours. Ctrl+C on the assisted computer revokes access immediately. Unix uses a temporary Python pipe watcher to stop ordinary owned descendants on host death or command completion. Native macOS validation is pending. POSIX cleanup is not a security sandbox against deliberately detached processes.

Internet route

Both computers use outbound TLS WebSockets for pairing. A SPAKE2 exchange authenticates the shared code and encrypts the SSH identities and Transit ticket. Both then make outbound connections to the Transit relay, which joins their streams. SSH performs fresh key exchange and checks the paired keys. The relay forwards ciphertext. This is why no port forwarding is needed.

The default public Transit uses TCP 4001. If that port is blocked, an explicitly configured WebSocket Transit relay can use HTTPS infrastructure. The included optional Python relay supports that deployment; this release does not promise a public 443 fallback or direct listeners. See implementation evidence.
