ssh-snakehole specification / 5. Files, processes and platforms

What access and cleanup actually mean

Command execution

The host executes as the account running Python, with that account's actual permissions. Use a fresh child process per exec channel, home directory as the initial cwd, and binary pipes. The Windows default is powershell.exe -NoLogo -NoProfile -NonInteractive -Command COMMAND. Linux/macOS default is /bin/sh -c COMMAND. This removes the existing Linux dependency on Bash and its login-profile side effects. Applications may provide a different executor.

The library's run(command) passes one string to the selected shell. Command length is capped at 64 KiB of UTF-8 with no NUL bytes. It is an authorized operator payload, so the package does not escape it as though it were a filename. The run_argv(argv) path starts the given executable directly with shell=False. Its custom SSH channel request is specified in the API chapter, and does not affect ordinary exec interoperability.

Do not accept SSH environment requests or a remote-selected shell executable. Child environment starts from the host process with pairing/credential/test configuration variables removed. Preserve the host's ordinary PATH. Do not put ticket/code/key material in environment variables, command arguments or cwd. On Windows, resolve the shell from the trusted system Windows directory, not the current working directory. Clear only the product's injected state and known PowerShell host contamination where required; do not erase unrelated environment settings indiscriminately.

Drain stdout and stderr concurrently, apply backpressure and stream stdin. Closing stdin closes the child pipe, not the output pipes. A timeout or channel cancellation starts child cleanup and then drains bounded remaining output for at most two seconds. Return native exit status when known, distinguish signal termination on POSIX, and avoid pretending a Windows process was killed by a Unix signal.

Piped shell requests start the same OS shell without a PTY. Programs requiring interactive terminal APIs may fail. Do not manufacture terminal dimensions, translate ANSI output, run a terminal emulator, or advertise PTY acceptance. The initial implementation focuses on agent commands and file transfers.

SFTP v3 contract

Use the deployed v3 protocol defined by filexfer draft 02, plus only implemented OpenSSH SFTP extensions. This is an expired draft, not an RFC. Implement INIT/VERSION, OPEN/CLOSE, READ/WRITE, LSTAT/STAT/FSTAT, SETSTAT/FSETSTAT where supported, OPENDIR/READDIR, REALPATH, MKDIR/RMDIR, REMOVE, RENAME, READLINK and SYMLINK where the OS permits. Unsupported attributes/extensions return the proper status rather than fabricated success.

Handles are random opaque identifiers bound to one SFTP channel and one object. They are not raw file descriptors or serialized filesystem paths. Permit at most 64 live handles and 32 outstanding client requests per SFTP channel. Cap SFTP packets at 256 KiB, file read/write chunks at 64 KiB, paths at 16 KiB of encoded data, and returned directory batches at 128 entries or 64 KiB. Reject unknown/duplicate request IDs that would corrupt outstanding state. Large offsets and sizes use checked uint64 values; filesystem errors become documented SFTP status codes.

Advertise posix-rename@openssh.com only where os.replace implements replacement semantics. Advertise fsync@openssh.com only for real opened file handles with os.fsync. Do not advertise ownership, permission or symlink capability uniformly across platforms. Permissions/UID/GID fields must reflect meaningful platform data or be absent. Errors must not disclose host traceback, local key paths or process environment.

Paths

Library paths are Python strings. On POSIX, the low-level SFTP interface may accept byte paths, preserving undecodable filenames; high-level string conversion uses filesystem encoding and surrogateescape. Windows accepts valid Unicode paths and rejects surrogate/NUL forms it cannot address. String APIs never use lossy replacement encoding. A remote path is resolved on the remote OS, not with the operator's pathlib rules.

Windows high-level clients normalize C:\Users\Alice\file to /C:/Users/Alice/file for SFTP. Server translates that form to a local drive path. Relative paths start under the host's home. Reject device namespace paths such as \\.\, \\?\GLOBALROOT, named pipes, alternate data-stream syntax outside a drive colon, embedded NUL and ambiguous drive-relative forms such as C:file. v1 rejects UNC paths explicitly; support would require a separately tested filesystem policy.

The default grants normal filesystem access for the host account, including absolute paths. It does not chroot into home. A caller-supplied file policy may disable SFTP entirely or allow operations through caller-owned file objects. Do not claim a simple path-prefix test safely confines an adversarial peer against symlink/reparse races. General sandboxed SFTP is outside v1.

Transfer commit

put and get default to no overwrite. Create a random sibling temporary file exclusively, transfer bounded chunks, close it after successful writes, and only then commit. overwrite=True requests atomic replacement when supported. Source metadata and final destination are never interpreted as shell text. Do not create missing parent directories implicitly.

On POSIX local no-overwrite commit can use a link-based exclusive commit followed by unlinking the temporary file. On Windows, non-replacing rename behavior must be tested on the supported filesystem. Remote no-overwrite uses standard SFTP RENAME only if the server's semantics are verified. If safe exclusive/atomic behavior cannot be established, raise AtomicCommitUnavailable rather than performing a check-then-overwrite race. There is no silent weaker fallback.

Downloads use fsync before local commit. Uploads request remote fsync only when advertised and the caller requests durability. Successful rename means committed visibility, not guaranteed persistence across power loss unless file and parent-directory durability are supported. A failed transfer leaves the original destination unchanged and reports whether a temporary file may remain. Cleanup only removes the exact random path owned by this transfer, never a glob or unrelated file.

Transfer counters are bytes copied, not percentage guesses. Before commit, validate the source has not changed in a way detected by the available size/mtime/handle metadata. A requested end-to-end SHA-256 comparison is an optional explicit operation; routine streaming must not read every file twice. There is no transparent resume after disconnect.

Privilege modes

No protocol operation elevates the process. POSIX admin mode requires effective UID zero. Windows checks the current process token through OpenProcessToken and GetTokenInformation, including TokenElevation and TokenUser, using typed standard ctypes wrappers. Admin intent without verified elevation fails before allocating a code. User mode rejects an elevated process unless admin mode was explicit. Do not infer privilege from username or writable directories. If an OS check cannot establish privilege, fail the default executor's readiness check rather than opening ambiguous access.

--admin uses an already elevated interpreter in v1. The console gives a concrete launch instruction when it is not elevated. Automatic UAC/sudo remains a deliberate usability gap against SSH Magic, because elevating a user-writable Python interpreter/package safely requires an installation trust policy. It is not claimed to be impossible from Python. No cross-user cache sharing or implicit migration between user/admin roots.

Elevated users must run code from an administrator-controlled interpreter and package installation, including its stdlib, imported dependencies and DLL search locations. Checking only the zipapp hash is insufficient if Python's own installation is user-writable. An eventual self-elevation feature would need OS-verified protected staging, interpreter/dependency ownership checks and explicit UAC/sudo launch semantics. Do not add a speculative escalation flag or unsafe PowerShell workaround in v1.

OS adapter contracts

Primary authorities are Python ctypes, Microsoft's Job Object overview, assignment constraints and token information API, plus the Linux parent-death specification. The startup protocol and isolation rules below are this product's design.

Use ctypes only for the built-in OS functions listed here. Every function has explicit argtypes/restype, pointer-sized handle definitions, architecture-correct structure layouts and checked errors. Load Windows system DLLs from trusted system locations with restricted search semantics; never search cwd for kernel32/advapi32. No product API or network message can name a DLL/function. Do not use undocumented Python internals or call OpenSSL/libsodium through ctypes. OS wrappers are included in the Python source/provenance inventory.

Windows command startup uses CreateJobObjectW, SetInformationJobObject with JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE, OpenJobObjectW, AssignProcessToJobObject, TerminateJobObject and CloseHandle. The parent creates a randomly named job with a private DACL and a non-inheritable handle. It launches its own fixed Python startup worker through asyncio subprocess. The worker opens that job, assigns itself, closes its temporary job handle, signals ready, and only then receives the validated operator payload. It cannot start payload before readiness. Parent disappearance before readiness means no payload; afterwards the parent is the only lifetime-handle owner, so kill-on-close works. Job-name collisions or unexpected existing objects fail startup.

Job containment is process management for cooperative authorized workloads, not a sandbox against an operator with the same account's full rights. Such an operator may use OS managers or interfere with same-account objects/processes. No cleanup guarantee extends to deliberately defeating the host. At normal close the parent actively terminates the job rather than relying only on last-handle closure.

This avoids an assign-after-running race without assigning the application's own process to the job. Default child job inheritance contains descendants. Do not enable breakaway flags, inherit the parent's job handle into workers/payload, or apply a global job to unrelated application processes. A worker setup failure closes its pipes and job, reports PlatformContainmentUnavailable, and executes no operator code. Test startup races and nested jobs on x64/ARM64. The worker's bootstrap/control channel carries no SSH secrets and uses a bounded length-prefixed payload, at most the 64 KiB execution-request limit, distinct from later binary stdin bytes.

Linux startup may use a Python worker to set prctl(PR_SET_PDEATHSIG) and validate the expected parent immediately after setting it, then run only the validated payload. Spawn from a long-lived owner thread because the kernel's parent-death semantics concern the creating thread. Do not use unsafe preexec_fn from a multithreaded embedding application. The worker handles parent death by cancelling its owned command group when possible; forced kill, set-ID/capability changes and deliberately detached children remain limitations. macOS uses normal process-group cleanup and states the forced-parent-death gap explicitly.

Files and local state

Library memory-only mode writes no credentials or installation files. Optional CLI state lives under the user's own product directory: Windows %LOCALAPPDATA%\ssh-snakehole, Linux $XDG_STATE_HOME/ssh-snakehole or ~/.local/state/ssh-snakehole, macOS ~/Library/Application Support/ssh-snakehole. Validate absolute root resolution; never use cwd-relative state for privileged operations. Product installation and state roots are separate.

POSIX private state uses owner checks, 0700 directories, 0600 files and symlink rejection with exclusive creation. Windows uses ctypes OS security APIs to create/check protected DACLs granting the current token SID and SYSTEM, rather than treating chmod as ACL enforcement. Use handle-based security/path checks, reject reparse-point substitution and protect before writing secret data. Admin roots grant administrators/SYSTEM and require a protected ancestor chain. Persisted tickets remain encrypted on every platform as defense in depth. Shared/untrusted roots are unsupported.

Windows ACL wrappers use token SID lookup, explicit security-descriptor construction and documented handle-based GetSecurityInfo/SetSecurityInfo and file creation semantics. Free OS-allocated security buffers with the correct OS allocator and close every token/file handle once. Token/security failures fail closed. Do not apply recursive ACL changes to a user's profile or assume a private child directory fixes a user-writable privileged ancestor. Local administrator or endpoint compromise remains outside the vault's protection.

The handle-based ACL contracts come from Microsoft's GetSecurityInfo and SetSecurityInfo documentation. v1 must prove behavior on local supported filesystems; network/virtual filesystems that cannot establish equivalent protection are rejected for secret state.

Use cross-process advisory locks through stdlib platform modules for the CLI's host and help state. Keep the lock file outside a replaced document and hold an open locked handle for the lifetime of the operation. Never infer liveness from PID alone or remove another holder's lock file. Public host status contains session ID, expiry and phase, never a code or key. A repeated open prints the code only if its creator explicitly kept it in its live console; a second process cannot recover a redeemed or hidden code.

Async subprocess support requires Windows Proactor behavior and Unix subprocess-capable loops, as documented by Python's platform support. Reject a Windows Selector loop before offering default execution, or let a caller provide a working executor. Importing the package never changes the caller's event-loop policy.
