Strict KEX and the cipher documents cited here include expired Internet-Drafts; they are deployed OpenSSH behavior, not final RFCs. Pin these profiles and implementation fixtures. Release review must check whether a later standard or security fix changes the requirements. Native client adapters require peers supporting this modern profile. Fail with UnsupportedPeer when negotiation cannot meet it. No algorithm downgrade or automatic legacy mode.

Cryptographic implementation contracts

Use standard hashlib.sha256, hashlib.sha512, hmac and secrets.token_bytes. Implement HKDF-SHA256 with the extract/expand semantics of RFC 5869, including an all-zero hash-length salt when absent. Keep the Wormhole/Transit labels exact. SSH uses its own specified key derivation, not HKDF.

The SPAKE2 port retains upstream symmetric mode, its fixed blinding point, password-to-scalar mapping, identity/transcript calculation and peer checks. Validate encoded group membership and reject invalid, identity and reflected points according to the pinned reference. Do not reuse a SPAKE scalar or serialize unfinished PAKE state to disk. Create known-answer transcript fixtures with deterministic test entropy; production cannot select test entropy through an environment variable.

Ed25519 signing uses independent 32-byte seeds for the host and operator. Verification rejects noncanonical scalars/encodings and disallowed low-order points; fixtures must establish the exact accepted verification profile and independent OpenSSH compatibility. The signing operation signs the SSH exchange hash or userauth payload as specified, not a prehashed substitute. Public key blobs contain the SSH algorithm string and 32 public-key bytes.

X25519 uses the RFC 7748 ladder and input processing, with fresh 32-byte entropy per key exchange. Reject a wrong-length peer public value and all-zero shared result. SSH interprets the resulting shared-secret byte string as a big-endian unsigned integer before mpint encoding under RFC 8731. This differs from the little-endian internal curve arithmetic. Include fixtures with leading-zero and high-bit shared results; an endianness mistake here can look plausible while never interoperating.

Mailbox SecretBox uses XSalsa20-Poly1305, a 32-byte key and a fresh 24-byte nonce. Its API returns nonce followed by the NaCl-compatible MAC/ciphertext. Port the used construction and Salsa/HSalsa operations from audited specifications/permissive references. libsodium's construction is a differential reference, not an imported DLL. Validate the tag before exposing any plaintext.

OpenSSH ChaCha20-Poly1305 is different from the IETF RFC 8439 AEAD. Its key material is 64 bytes split into payload and header keys. It uses an eight-byte sequence-derived nonce, separately encrypts packet length, obtains the one-time Poly1305 key from the payload cipher and starts payload encryption at counter one. The authenticated bytes are the encrypted header plus encrypted packet. Match the pinned OpenSSH construction byte for byte; do not swap in an RFC 8439 function just because its name resembles it.

Tag comparisons use hmac.compare_digest. This does not make Python integer arithmetic constant-time. Python curve operations, interpreter behavior and allocations can leak timing. The implementation MUST publish this limitation and undergo review of the intended threat model. It MUST NOT advertise constant-time crypto, guaranteed key erasure, FIPS validation or equivalence to a mature native stack.

SSH packet and handshake state

Exchange SSH-2.0-ssh_snakehole_1 identification lines with CRLF. Limit a peer identification line to 255 bytes and accumulated pre-banner text to 4096 bytes. Validate the protocol version before constructing a KEX state. Preserve exact identification/KEXINIT bytes in the exchange hash. Do not hash normalized banners or reconstructed JSON-like structures.

Packet parsing must work under arbitrary fragmentation and coalescing. Limit SSH packet_length to 256 KiB, reject impossible padding and cap every nested string/list before allocation. Random padding follows the selected cipher's alignment rules. Sequence numbers are directional uint32 values. Do not dispatch unauthenticated payload bytes. Length decryption used to frame an AEAD packet may occur before tag verification, but it may only guide a bounded read.

State transitions are identification, initial KEX, NEWKEYS, service request, user authentication and connection channels. Strict KEX markers are sent in the initial algorithm list, enforced before accepting later packets, and never treated as actual exchange algorithms. No IGNORE/DEBUG/UNIMPLEMENTED injections are accepted during initial strict KEX. Reset directional sequence numbers at the prescribed NEWKEYS boundary. Reject peers without strict KEX because this profile's bulk cipher needs that defense.

KEXINIT contains all required directional cipher/MAC/compression lists and empty language lists, with fresh random cookie bytes. Cap each list at 4096 bytes and 64 names. Apply client-preference negotiation exactly, without selecting an extension marker as an algorithm. Handle first_kex_packet_follows under the SSH transport rules, including consuming exactly one incorrectly guessed KEX packet when required. A strict-KEX violation remains a failure rather than a reason to relax parsing.

For every KEX, compute and validate the exchange hash, host signature and derived directional keys. The first exchange hash is the session identifier for later authentication and rekeys. Pin the entire expected host public key blob; hostname text and a relay token are not host identity. Initial key exchange does not authorize command execution.

Rekey after 256 MiB in either direction, one hour since the previous key exchange, or before sequence exhaustion, whichever occurs first. These are conservative product limits, not alleged standard defaults. Pause outbound channel data during KEX in bounded buffers, keep existing channels and window accounting, reject conflicting exchanges, and complete within ten seconds. Simultaneous peer/local rekey must converge through one negotiated exchange. Never reset or reuse a key/nonce state except as prescribed with fresh keys.

Authentication and key formats

The host accepts exactly the paired operator public key. An unsigned public-key probe may receive PK_OK only for the correct key and current invitation. A subsequent signature covers the correct session ID and complete userauth request. Reject username/service/algorithm mismatch, expired invitation, none/password/keyboard-interactive/hostbased methods and any key not in the one-entry authorization record. Cap failed authentication messages at three per connection. The host's two-minute first-auth deadline starts when pairing is accepted.

Core storage uses fixed-size seeds and public blobs; no PEM parser is needed for the core. Native export writes an OpenSSH Ed25519 private-key container using the specified OpenSSH key format, without bcrypt encryption in the minimal runtime. That export is explicit, limited to the secure-storage conditions in chapter 7 and removed when forgotten. Arbitrary imported private-key formats and encrypted OpenSSH-key parsing are outside v1.

Connection channels

Implement RFC 4254 session channels, open confirmation/failure, window adjust, data, stderr extended-data, EOF, close, channel requests and exit status/signal. Only exec, piped shell and the sftp subsystem are accepted. One execution/subsystem request is allowed per channel. Reject PTY, env, agent, X11, direct-tcpip, forwarded-tcpip and tcpip-forward. Unknown requests receive failure when a reply is requested; unsupported required behavior fails explicitly.

Advertise a 256 KiB channel receive window and a maximum data chunk of 32 KiB. Replenish credits only as the consumer releases bytes, with a global inbound memory budget of 16 MiB across hosts/connections owned by one library runtime. Permit sixteen session channels per SSH connection, sixty-four per host, and eight authenticated connections per host. Scheduling must allow stderr, stdout and stdin to progress independently; an unconsumed output stream cannot permit unbounded buffering.

Send a keepalive global request after fifteen seconds without useful inbound activity, and require a reply within ten seconds. A failure reply still proves the peer is alive; a timeout does not. Do not reset application execution deadlines because keepalive succeeds. Serialize reply-wanted global requests because SSH replies do not include request IDs. Channel request replies follow the same discipline per channel.

On peer EOF, drain authenticated bytes already received, then expose EOF once. EOF is directional and does not equal full close. Capture exit status before channel close where available. A connection loss before status leaves the command outcome unknown, even if stdout looked complete. Cancellation kills owned execution according to the platform chapter and closes that channel, never silently the entire host.

Remote host closure

Define SSH global request close@ssh-snakehole, want-reply true, with a payload consisting of one SSH string containing the session ID. The host validates identity and session, atomically marks the invitation CLOSING, refuses new authentication/channel requests, acknowledges acceptance, cancels owned work and closes all streams/listeners. Default cleanup budget is five seconds.

The client reports accepted once it receives success and transport_closed when EOF follows. Neither proves a deliberately detached process ended. A disconnect without the success reply is CloseUnconfirmed; retain the ticket for a safe explicit retry. Retrying closure on an already unreachable host cannot distinguish expiry from network loss. The local console's close always acts on its owned host without needing the relay.

Once close acceptance is known, the CLI may erase its vault entry even if network EOF is delayed; it records the result before deletion. forget only drops local credentials and does not pretend to close the target.
