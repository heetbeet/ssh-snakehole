ssh-snakehole specification / 8. Security and failures

Security claims with defined limits

Who is trusted

ActorTrust and authority
Host ownerTrusts the installed Python/package and intentionally opens their account's access. Keeps the foreground host visible and can end it locally.
Code holderCan attempt to become the one paired operator. Once paired, receives full enabled host-account execution/filesystem authority until closure/expiry.
MailboxUntrusted for message confidentiality/authenticity; PAKE and authenticated phase encryption protect those. It still controls availability and sees IPs, AppID, timing, nameplates and opaque messages.
Transit relayUntrusted for SSH confidentiality/authentication. It sees endpoints, token, timing, traffic sizes, pre-encryption SSH negotiation and can drop/replay/reorder bytes or deny service.
Package publisher/bootstrap originTrusted to supply executable code. TLS/hash checks cannot save a user from deliberately malicious publisher content.
Local user/admin or malwareCan potentially read process memory, capture passphrases, tamper with user-writable code or interfere with files. The package does not protect a compromised endpoint.

A code is a short-lived invitation secret. The inspected word-list implementation selects each word from a 256-entry position-dependent list using an independent random byte. Four words provide 32 bits of word-choice entropy; the public numeric nameplate adds no password secrecy. PAKE limits an active guess to a protocol attempt and prevents a mailbox ciphertext from becoming a simple offline password oracle. It does not prevent an attacker who already knows the code from pairing first. A failed or third-party pairing consumes the offer and requires a new code.

Mailbox TLS authenticates its configured service and protects traffic to that service. It does not replace PAKE. Use ssl.create_default_context, hostname checking, certificate verification and TLS 1.2 minimum, as supported by stdlib ssl. Do not allow plaintext mailbox URLs in the default product, disable verification, accept every certificate or follow credential-bearing cross-origin redirects. Explicit local development fixtures use a trusted test CA. Disable TLS key logging for product-created contexts even if an inherited SSLKEYLOGFILE would enable it.

Standard-library SHA/HMAC/entropy are inside the agreed dependency boundary. The Python ports of signature/group/stream-cipher operations have a separate review obligation. Neither test-vector success nor reuse of mathematical formulas establishes resistance to timing attacks or implementation mistakes.

Host state and deadlines

StateEntry/exit conditionPermitted work
STARTINGReadiness and resource creation. Failure cleans owned resources before any code is displayed.No peer work.
OFFEREDNameplate/code available. Ten-minute pairing deadline begins.One PAKE exchange; no SSH authorization.
PAIREDValidated offer acceptance/ready. Code is consumed; first SSH auth deadline is two minutes.Transport attempts with pending/auth limits.
ACTIVEFirst authorized SSH authentication.Enabled command/file channels, reconnects and authenticated close.
CLOSINGLocal close, confirmed remote request, expiry or fatal host error.No new auth/channels; cleanup/close reply only.
CLOSEDOwned access resources closed; cleanup result recorded.No code/ticket reuse or implicit restart.

Two-hour lifetime begins at host start, not first connect. Keep a monotonic elapsed deadline and a UTC expiry. A one-second lifecycle check and every authorization/dispatch point enforce whichever local bound is reached first. On resume, check before handling queued peer work. Large forward wall-clock jumps may close early; backward jumps cannot extend the monotonic runtime budget. These clocks do not prove exact real-world elapsed time through every OS suspend/clock manipulation, so document the behavior rather than promise a trusted hardware timer.

Connector pairing has a 120-second deadline. Mailbox reconnect before that deadline uses exponential backoff with jitter, from one second to at most thirty seconds, retaining deduplication state. Never restart PAKE with a new scalar under the same exposed code after an authentication failure. A mailbox disconnection after ready does not invalidate the already accepted ticket.

Host's waiting relay socket refreshes before the relay's pending timeout, with bounded jitter. Connection failure backoff cannot outlive the host deadline. An authenticated SSH disconnect does not close the entire invitation; the owner or expiry does. No background service restores it after the foreground process ends.

Protocol packet lengths are checked before allocating or decrypting large buffers. A WebSocket adapter must apply limits while fragments arrive, not after assembling an unlimited message. Avoid JSON recursive nesting attacks; cap nesting at eight and records at 128 keys. Offer/accept/ready are shallower and enforce their exact schema. Network inputs cannot tune limits or KDF cost.

Failure pointRequired state after failure
Download/install interruptedOld valid launcher/artifact stays active. Partial file is not imported. Owned temporary residue is acceptable.
Wrong code or PAKE authentication failureNo ticket, no operator authorization; host closes invitation. Fresh code required.
Offer accepted but ready not deliveredOperator has no reusable accepted ticket; host first-auth timeout closes if nobody authenticates.
Ready received; initial SSH dial failsTicket retained in memory/vault for explicit retry before expiry. No command executed.
Host key mismatchDisconnect before userauth/commands. Pin remains unchanged; do not prompt accept-new-key.

Transfer fails before commitPrior destination survives; owned temporary file removed if reachable. Report possible residue.
Connection fails during commit responseTransfer commit state is unknown. Caller must inspect, never assume it failed and overwrite on retry.

Expiry during a commandRevoke all access and start owned-process cleanup immediately. Expose interruption, not a fabricated normal exit.

Privacy and diagnostics

Host code is deliberately displayed only in the host's console before redemption. Ordinary status/logs never include it. Strip control characters, terminal escapes and newlines from host/user/service display labels and MOTD before display. Never treat relay-supplied text as instructions, shell text, markup or a new endpoint configuration.

Debug logs include stage, stable error code, nonsecret session identifier, elapsed time and transport type. Secret fields and command/transfer content are excluded even at debug level. Optional packet traces require a development-only build and explicit secret-handling documentation; no product flag silently dumps decrypted traffic. Python tracebacks should not include repr of tickets/private buffers.

Deletion removes product-owned files, not all filesystem traces, swap, terminal scrollback or immutable Python copies. Disk vault encryption reduces exposure while locked. Best-effort overwriting mutable buffers cannot guarantee erasure. Key logging, crash dumps and a compromised process remain risks the package cannot eliminate.

Decisions that remain release gates

The architecture is specified; its feasibility claims still need evidence. Required decisions are whether measured pure Python crypto performance meets the product use case, whether an independent reviewer accepts its timing-threat exposure, which relay capacity/443 deployment supports launch, and whether the OS containment/storage wrappers and protected admin-launch policy pass review. A failed gate calls for a documented product change or dependency-policy change, not an insecure fallback.
