ssh-snakehole specification / 7. CLI and installation

Small commands around the same library

The installed command is ssh-snakehole, package import is ssh_snakehole, and the fallback is python -m ssh_snakehole. No wh, ws or other short PATH alias. The repository/release identity is new; this specification does not publish or reserve it.

PowerShell quoting examples use a single quoted command argument; CMD and Bash require their own quoting examples in the final release docs. Do not claim a complex one-liner is shell-universal. Code on argv may enter shell history, so prompted connect is the recommended CLI form.

Download and run

Keep boot.ps1 and boot.sh at the eventual repository root on master. They are small launch adapters; all protocol/crypto/installation logic is Python. PowerShell and Bash are optional delivery shells already available on those platforms, not imported runtime helpers. A Python-only download path must also be documented for systems without those shells.

The desired short PowerShell form is irm https://RAW_ROOT/boot.ps1 | iex; the Bash form is curl -fsSL https://RAW_ROOT/boot.sh | bash. RAW_ROOT is a placeholder until a repository/domain exists. Final commands must be copied and tested verbatim against published artifacts. Do not substitute an invented GitHub URL and call it a functioning bootstrap.

When a command needs arguments, download the script to a temporary filename and invoke it with explicit arguments rather than relying on iex argument forwarding. A PowerShell wrapper using $env:TEMP must be tested both from PowerShell and from CMD's outer powershell -NoProfile -ExecutionPolicy Bypass -Command ... form. %TEMP% is CMD expansion; it is not portable PowerShell text. Bash bootstrap defaults to open with no arguments and passes exact arguments when invoked as a file.

Bootstrap locates a supported interpreter, checks its version/features, downloads one versioned source/data-only zipapp over validated HTTPS, and runs it. On Windows probe py -3 and real Python executables; do not mistake an App Execution Alias for a working interpreter. On Unix probe python3. No automatic native Python installation belongs inside the pure Python claim. If no interpreter is present, exit with one concrete interpreter-install instruction and the exact unsupported-runtime reason. A later optional packaged interpreter is a separately disclosed native distribution.

A healthy installed version is reused unless update is explicit. Temporary download residue is acceptable. Cache writes are atomic and lock-protected; a truncated/invalid archive is never imported. Do not execute from a shared predictable path in admin mode. Downloaded files remain unprivileged until the user deliberately uses an administrator-controlled installation.

Integrity without unnecessary machinery

Use validated HTTPS and one release manifest recording the artifact version, size and SHA-256. Check it once on download and on offline import if the artifact is supplied externally. The SHA catches corruption and release mismatch; a hash downloaded from the same compromised source does not independently authenticate a publisher. Do not hash every dependency repeatedly at startup, add multiple parallel signatures without an actual trust model, or build a bespoke updater.

Published source bootstrap on a moving branch is a convenience/trust tradeoff. Supply a pinned-release alternative for reproducibility and privileged operation. A signed release may be added only with a concrete key distribution/revocation policy. Release design must be honest about who can modify the initial script.

Credential persistence

Core API never saves a ticket. CLI persistence uses one encrypted vault entry named help. On first connect, the operator chooses a passphrase through getpass; subsequent standalone exec/put/get/close prompts to unlock it. Memory mode and the importable API avoid repeated prompts. Do not add a secret-bearing localhost broker merely to preserve the old CLI shape.

Vault envelope is strict JSON containing schema="ssh-snakehole-vault/1", fixed KDF identifier, 16-byte random salt, fixed parameters, 24-byte nonce and base64 ciphertext. Encrypted plaintext contains the validated ticket, alias, code fingerprint and creation time. Use hashlib.scrypt with N=32768, r=8, p=1, dklen=32 and a 64 MiB maximum allocation, followed by the same audited SecretBox construction. Refuse missing scrypt support for vault operations; memory mode still works. These parameters are a proposed baseline subject to platform cost measurements, not a guarantee that weak passphrases become strong.

Reject file size over 16 KiB before parsing. Reject attacker-selected KDF costs and duplicate/extra fields. Passphrase minimum is twelve characters for CLI creation; encourage a generated multiword phrase and never claim character count measures entropy. Do not store a passphrase in the vault, environment, launch arguments or config. Wrong passphrase/corrupt vault yields one generic VaultUnlockFailed and writes nothing. An unlocked ticket lives only as long as that process needs it.

Do not expose the code fingerprint in plaintext as an offline guess oracle. All fields that identify the code/host/ticket remain encrypted. File protection still matters for substitution/deletion; disk encryption is confidentiality, not availability. User/admin state uses different roots and is never merged automatically.

Repeat and conflict behavior

open acquires the CLI host lock before allocating an invitation. A second invocation prints nonsecret phase/expiry and exits without touching the first host. It cannot read the live code from another process. Stale status is removed only after lock ownership and session validation prove no live holder. A PID match alone is insufficient.

connect holds the help-state lock. A saved ticket for the same code fingerprint is unlocked and retried without new PAKE. A different code with existing help state fails and tells the user to close or forget the current help entry. Corrupt state is never overwritten implicitly. Save an accepted ticket before initial SSH dial, so a post-pair network failure can retry. Pairing without ready acknowledgement does not produce a reusable ticket.

Install is atomic, manifest-driven and repeat-safe. Refuse replacing files not owned by this installation, downgrading implicitly, changing an active interpreter/artifact under running hosts, or deleting state outside the resolved product root. Remove denies active host or help entry; the user must close/forget deliberately. Never delete an existing unrelated command simply because its name matches.

Installed and offline artifacts

Build a source distribution and py3-none-any wheel for normal Python users. Build one zipapp containing the package plus audited wsproto/h11 and notices for download/offline use. Ship ssh-snakehole-offline.zip with the pyz, release manifest, licenses and install guide. It contains no native interpreter, executable sidecar, service registration or network dependency resolver.

Offline workflow is python ssh-snakehole.pyz install. Installation makes no internet requests. Operation across the internet still needs a relay, or an explicitly configured LAN direct path; offline install does not mean offline internet access. A wheel workflow uses pip with --no-index and a supplied complete local wheel set. The zipapp avoids requiring pip on the target.

The zipapp installer copies the artifact into a versioned per-user application directory and creates a full-name launcher pointing to the verified absolute interpreter and artifact. Quote spaces, Unicode, apostrophes and shell metacharacters correctly. Do not use the user's cwd to resolve either path. On update, write a new version then atomically switch the launcher. Keep a currently running version until it exits; old-version cleanup is bounded and only touches manifest-owned paths.

Windows uses a .cmd launcher and HKCU user PATH through stdlib winreg. Preserve REG_SZ/REG_EXPAND_SZ and unrelated tokens, compare existing entries case-insensitively and tell the user that new terminals pick up the change. No user32 broadcast is promised. Linux/macOS use a quoted POSIX launcher under a user bin directory. Explicit PATH installation adds one exact marked profile line after inspecting the user's shell/profile; conflicting/missing unusual profiles produce a manual export instruction. Never edit system profiles or replace the whole PATH.

Install from a normal terminal. Admin operation uses a separate protected environment. Permanent installation persists the package/launcher/PATH entry only. It creates no service, scheduled task, login item, firewall rule, router rule, SSH account or system sshd config. Remove restores only owned installation changes. Temp files may remain as allowed by the user.

Native SSH, SFTP and SCP integration

The primary agent integration is the importable API. Optional export-ssh help DIRECTORY unlocks the vault, writes a dedicated config/known_hosts/identity and supplies proxy help as the byte-stream ProxyCommand. This uses an existing native client only when the operator chooses it. It is not a prerequisite for library operation. Proxy writes binary SSH bytes to stdout and diagnostics to stderr only.

Export requires a protected operator-selected directory. POSIX enforces owner/mode checks; Windows uses the audited ctypes DACL adapter. Fail before writing secrets if protection cannot be established. Windows exported key ownership/ACLs must also pass native OpenSSH's permission checks. Export is optional on every platform; the Python client works without disk private keys.

Export pins the exact host blob, disables agent/forwarding/password/keyboard-interactive auth, uses only the dedicated identity and known_hosts, and avoids global SSH configuration mutation. No default ~/.ssh/config rewrite. Modern scp can use SFTP; legacy SCP protocol is not implemented. Proxy consumes the unlocked ticket in its own invocation; the first version may prompt for the vault passphrase on its controlling terminal. Noninteractive agents should use the Python API rather than rely on a prompting ProxyCommand.
